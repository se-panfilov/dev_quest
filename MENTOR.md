# Для ментора: настройка (один раз) и ревью (раз в неделю)

Ментор — тот, кто проверяет код: родитель, старший брат, знакомый разработчик. Для настройки нужно
около часа, дальше — 5–10 минут на каждый PR.

## Как это устроено

```
Ученик (свой форк)                 GitHub                          Ментор
──────────────────                 ──────                          ──────
карта квестов (Pages)       ──►  читает PR и метки через API
делает квест в projects/
git push quest/w1-q4        ──►  Action: тесты + PR с отчётом ──►  письмо «новый PR»
                                 (внутри форка)                    ревью, похвала, метки
                            ◄──  merge                        ◄──  Approve + Merge
XP, уровень, бейдж и отзыв появляются на карте
```

У ученика свой аккаунт GitHub и свой форк этого репозитория. Все PR живут **внутри форка** —
в оригинальный репозиторий ничего не уходит. Ментор — collaborator форка и мержит PR.

> Условия GitHub: аккаунт с 13 лет. Младше — заведите аккаунт на себя и отдайте его ученику,
> когда исполнится 13.

## Настройка

1. **Аккаунт ученика.** Создайте аккаунт GitHub (ник без настоящей фамилии — репозиторий и
   карта будут публичными). Включите двухфакторную аутентификацию.
2. **Форк.** Из аккаунта ученика: эта страница → **Fork** → *Create fork*. Имя оставьте `dev_quest`.
3. **Actions в форке.** В форке GitHub по умолчанию выключает workflows: вкладка **Actions** →
   *I understand my workflows, go ahead and enable them*.
4. **Права Actions.** Settings → Actions → General → *Workflow permissions*: **Read and write permissions**
   и галочка **Allow GitHub Actions to create and approve pull requests**. Без неё PR не создаются.
5. **Pages.** Settings → Pages → *Deploy from a branch* → `master` / `(root)`. Через пару минут карта
   доступна по адресу `https://<логин-ученика>.github.io/dev_quest/`.
6. **Ментор.** Settings → Collaborators → *Add people* → ваш логин. Затем в форке **Watch → All Activity**,
   чтобы приходили письма о каждом PR.
   Необязательно: Settings → Secrets and variables → Actions → *Variables* → `REVIEWER` = ваш логин.
   Тогда вы будете автоматически назначены ревьюером каждого PR.
7. **Защита master (желательно).** Settings → Branches → *Add rule* для `master`:
   *Require a pull request before merging* + *Require approvals: 1*. Тогда в master попадает только то,
   что вы одобрили. (На бесплатном аккаунте правила работают для публичных репозиториев.)
8. **Компьютер ученика.** Установите [WebStorm](https://www.jetbrains.com/webstorm/download/),
   [Git](https://git-scm.com/) и [Node.js LTS](https://nodejs.org/ru). WebStorm бесплатен для некоммерческого
   использования: при первом запуске выберите *Non-commercial use*. Плагины не нужны, всё нужное встроено.
   Настройки WebStorm (Settings: Ctrl+Alt+S, на Mac ⌘,):
   - На Windows: *Tools → Terminal → Shell path* → `C:\Program Files\Git\bin\bash.exe` (Git Bash):
     команды в карточках написаны для bash.
   - *Languages & Frameworks → Node.js → Node interpreter* — установленный Node.js LTS (обычно подхватывается сам).
   - *Tools → Web Browsers and Preview → Reload behavior → In browser*: **On Change** — страница в браузере
     обновляется сама, пока ученик печатает.
   - Отступы и переводы строк WebStorm берёт из `.editorconfig` в корне репозитория, отдельно настраивать не нужно.
9. **Вход в GitHub с компьютера.** Проще всего [GitHub CLI](https://cli.github.com/):
   ```bash
   gh auth login          # GitHub.com → HTTPS → войти через браузер
   gh repo clone <логин-ученика>/dev_quest
   cd dev_quest
   git config user.name "<ник>"
   git config user.email "<id>+<логин>@users.noreply.github.com"   # из Settings → Emails
   ```
   (Вместо `gh` можно SSH-ключ: `ssh-keygen -t ed25519` → Settings → SSH keys аккаунта ученика.)
10. **Аккаунты курсов**: [HTML Academy](https://htmlacademy.ru/) и [Code Basics](https://code-basics.com/ru).
    Хекслет понадобится только в мире 5.
11. **Закладка.** Карта квестов — стартовая страница браузера ученика.
12. **Первый квест.** Ученик проходит `w0-q1` «Создание персонажа»: вписывает имя, род для званий и имя
    ревьюера в `hub/config.js`. Через минуту после `git push` появится PR — это проверка, что всё
    настроено. Мержите — и карта узнаёт игрока.

## Ревью (5–10 минут на квест, примерно раз в неделю)

PR приходит с отчётом ученика и результатом автотестов. Внизу PR — свёрнутый чеклист. Коротко:

1. Работает ли? Видно ли понимание в отчёте?
2. **Одна конкретная похвала за действие** («причина найдена через Network»), а не за ум.
3. Максимум 1–2 улучшения.
4. Метки: `xp+25` / `xp+50` / `xp+100` за доп. испытания, `badge:*` за то, *как* сделано.
   Метки создаются сами при первой сдаче квеста.
5. **Approve + Merge** — квест засчитан. Или **Request changes** — доработка в той же ветке.

Ваш комментарий появится на карте под заголовком «Отзывы». Это главный источник признания,
поэтому пишите его ученику, а не себе. Тон — как взрослому коллеге: прямо, с юмором, без сюсюканья.

Метка `нужна-помощь` на PR значит, что в отчёте есть раздел «Вопрос».

## Обновления из оригинального репозитория

Когда в оригинал добавляются квесты или исправления: форк → **Sync fork** → *Update branch*.
Затем ученик делает `git checkout master && git pull`. Оригинал никогда не меняет `hub/config.js`
и `projects/`, поэтому конфликтов быть не должно.

**Если открываете PR вручную в веб-интерфейсе** — проверьте, что *base repository* — это форк,
а не оригинал (GitHub по умолчанию предлагает оригинал). Автоматические PR из Action всегда идут в форк.

## Необязательно, но сильно помогает

- **5-минутное демо раз в неделю:** ученик показывает, что сделал. Работает сильнее любых XP.
- **Награда за босса:** договоритесь заранее, что даёт каждый побеждённый босс.
- **Ретро после мира 1** (≈ 6 недель): продолжаем ли, что бесит, нужен ли платный HTML Academy.

## Как пройти квест самому

Сделайте свой форк (или работайте в форке ученика в своей ветке `quest/…`), пройдите квест и
закройте PR **без merge** — в прогресс ученика он не попадёт.

## Как менять план

Все квесты — в `hub/quests.js`: тексты, ссылки, XP, порядок. Карта перестраивается сама.
В текстах можно писать `{reviewer}` — подставится имя ревьюера из `config.js`.
Ручная отметка квеста без PR — `hub/progress.js`.
